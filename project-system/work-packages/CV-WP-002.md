## Type

## Objective

Create the first controlled inventory and initial classification of the Core ecosystem.

## Principles

Repository existence alone does not prove:

- ecosystem membership,
- project role,
- lifecycle state,
- authority,
- or successor relationships.

Unknown states must remain explicitly unresolved until reviewed.

## Allowed scope

- inventory known Core projects
- inventory observed repositories
- classify confirmed and unresolved projects
- document provisional portfolio tiers
- record missing repository identities
- record pending alignment reviews

## Out of scope

- application implementation
- API design
- integration implementation
- project renaming
- project merging
- authority transfer
- changing another Core repository
- final architecture boundaries

## Acceptance criteria

1. Machine-readable project registry exists.
2. Human-readable portfolio exists.
3. Classification model exists.
4. Confirmed projects and observed repositories are distinguishable.
5. Core-Dev remains represented even if its repository is unresolved.
6. SC-OrgaBase remains represented even if its repository is unresolved.
7. OrgaCore is not automatically equated with SC-OrgaBase.
8. AirCore receives no invented ecosystem role.
9. Archived repositories are not automatically active projects.
10. Human Maintainer reviews the inventory before commit.

## Human authority

Final portfolio membership, classification, project retirement, successor relationships and authority remain Core Vision / Human Maintainer decisions.
